# 长任务循环推进器

> 英文标识：`smart-loop`

## 核心哲学

**不审问，演绎用户意图。不盲跑，每轮量化门检。不僵死，失败自动降级。**

面向长周期、可迭代、需要多轮推进的任务：先用最少的信息推断出真实目标，把任务拆成熵减链，然后每轮带量化指标地推进，失败时有明确的降级路径而不是卡死。

---

## 快速决策树

```
任务是否能用 ≤3 个确定动作完成？
  YES → 立即做完，汇报结果
  NO  → 继续

五要素中"目标对象"是否缺失？
  YES → 问 1 个问题后继续
  NO  → 进入流水线

任务是否完全没有可量化维度？
  YES → 问 1 个问题（或使用默认指标）
  NO  → 进入五阶段流水线
```

---

## 五阶段流水线

### Phase 1: 本质压缩 + 概率推断

用五个要素把模糊需求压缩成结构化意图：

| 要素 | 问题 | 映射 |
|------|------|------|
| 行为主体 | 用户想扮演什么角色？ | 观察者 / 分析者 / 构建者 / 决策者 / 探索者 |
| 动作本质 | 压缩后的核心动作？ | 监控 / 采集 / 分析 / 优化 / 审计 / 评估 / 发现 |
| 目标对象 | 对什么执行？ | 数据源 / 代码 / 系统 / 项目 / 市场 |
| 价值链 | 信息→处理→产出的流向？ | 从哪来 → 怎么处理 → 产出给谁 |
| 可持续性 | 能迭代多久？ | 有限搜索（N 轮收敛）/ 无限监控 / 一次性 |

### Phase 2: 熵减链分解

```
高熵(未知) → [信息源]→[过滤层]→[处理层]→[产出层]→[验证层] → 低熵(结论)
```

### Phase 3: 8 维自动补全 + 计划自检

每个子任务必须包含 8 个维度：目标、成功标准、每轮动作、量化产出指标、产出物、输入依赖、停止条件、风险预判 + 降级策略。

补全后做 6 项自检 + 代价预估。不通过不展示。

### Phase 4: 路径展示

精简展示：总任务、本质压缩、熵减链、子任务概要、代价预估、控制指令。

### Phase 5: 自动执行

```
FOR EACH 子任务 IN 路径图:
    WHILE 停止条件未满足:
        a. 执行子任务动作
        b. 量化门检
        c. 更新状态文件
        d. 检查退出信号 → 触发降级策略
        e. 检查提前终止条件
```

#### 量化门检

每一轮都必须有可判定的推进指标，否则判定为退化：

| 任务类型 | PROGRESS | DEGRADED |
|---------|---------|---------|
| 优化 / 改进 | 数值改善 | 持平 / 退步 |
| 采集 / 研究 | 新增 > 0 | 新增 = 0 |
| 监控 / 追踪 | 在预期范围内 | 连续 N 轮无更新 |
| 评估 / 验证 | 新确认项 > 0 | 新确认项 = 0 |

连续退化达到阈值即触发该子任务的降级策略，不阻塞后续子任务。

---

## 关键原则

1. 先分类，再进流水线
2. 演绎意图，不反复审问
3. 按熵减链拆分，而非按功能罗列
4. 8 维自动补全，缺口不外露
5. 用文件传递中间数据，避免上下文膨胀
6. 退化不僵死 —— 有明确降级路径
7. 可中断、可恢复、可续跑
8. 全局超时保护

---

## 适用场景

- 需要多轮迭代、逐步逼近目标的研究或优化任务
- 执行周期长、中途可能失败的自动化流程
- 用户需求模糊、需要先演绎再确认的复杂请求
- 需要严格成本控制、要求随时可中断的任务
