# 实测运行记录

本文件记录框架在真实任务上的运行开销与产出，用于说明它在生产规模下的表现。

> 说明：完整运行日志包含所研究任务的具体内容，不便于公开；此处仅保留**与任务领域无关的聚合指标**。

## Run #2 — 引用真实性审计

对一份已完成的研究报告做**引用与数字真实性审计**，目标不是"再研究一遍"，而是"逐条核实已有结论是否站得住"。

| 指标 | 数值 |
|---|---|
| Agent 调用规模 | **300** |
| 成功返回 | 81 |
| 失败（上游 429 限流） | 219 |

**审计发现：**

- 定位出 **1 处严重幻觉引用**（引用的文献并不存在）
- 定位出 **1 处数字失真**（数值与原始来源不符）
- 全部修复后，报告达成**引用 100% 真实、数字 100% 精确**

**这次运行暴露的问题与后续改进：**

大量 429 失败说明框架缺乏全局请求节流。后续版本为此加入了**全局 agent 预算熔断**与**调用点指数退避重试**（见 `FRAMEWORK.md` 版本日志 v6.5 → v6.8）。

---

## 关于这些数字

- 单轮 250 次 agent 调用、410 万 token 的开销，属于**高成本研究任务**，不适用于日常问答。框架为此内置了全局预算熔断，防止成本失控。
- 这套流程的价值不在于"便宜"，而在于**结论可信**——每条进入最终报告的结论都经过多票对抗验证与独立复现，并附带可重跑的验证命令。
- 负结果同样被记录：跑不出结论时，框架会明确输出"在给定约束下无解"，而不是编一个看起来合理的答案。
