# Multi-Agent Research Framework — 入口

## 这是什么

**注意：这不是一份"照着做"的指令，而是一个 Workflow 脚本的入口。**

本目录下的 `workflow.js` 是一个可执行的 Workflow 脚本（1,134 行），由 Claude Code 的 Workflow 引擎运行——脚本会**确定性地派生大量子 agent**，不是靠你读一遍规则再模仿。所以调用方式是**执行脚本**，不是加载指令。

## 解决什么问题

当一个研究任务足够复杂、足够开放时，直接让模型去查、去总结，得到的结果**无法判断真假**：不知道哪条结论有据可查，哪条是模型编的，哪条虽然为真但超出了问题边界。

本框架的答案是把「约束」和「验证」变成流程里的**结构性环节**，而不是靠 prompt 里写一句"请确保准确"。

**7 阶段**：制宪会议 → 问题分解 → 4 队并行求解 → 对抗验证 → 评分 → 综合合成 → 多轮修补

## 安装

把本目录（`multi-agent-research/`）整体复制到 `~/.claude/skills/multi-agent-research/`。`workflow.js` 必须和本文件在同一目录下——脚本通过相对路径引用它。

## 调用

```javascript
const result = await Workflow({
  scriptPath: "<本技能目录>/workflow.js",
  args: {
    task: "<复杂研究任务>",
    config: {
      constitution: true,    // 启用前置制宪会议
      patchLoop: true,       // 启用多轮修补（对已有产出做审计时用）
      maxPatchRounds: 1,     // 修补轮数上限 (1-3)
      votes: 5,              // 每条结论的对抗验证评委数
      refuteRequired: 3,     // 淘汰阈值 (≥3/5 反驳即淘汰)
      maxFetch: 15,          // 抓取预算
      maxVerify: 25,         // 验证结论数上限
      teams: ["T0", "T1", "T2", "T3"]
    }
  }
})
```

## 四支队伍的视角（内置）

| 队伍 | 策略 | 关注点 |
|---|---|---|
| T0 主攻手 | 权威 / 主流 / 一手 | 官方文档、机构报告、学术论文、一手数据与基准测试 |
| T1 逆势者 | 怀疑 / 反证 | 反驳证据、攻击常见假设、挖掘反例 |
| T2 实务派 | 落地 / 实操 | 真实案例、实现细节、从业人员视角、成本与约束 |
| T3 前沿哨 | 最新 / 边界 | 近期新闻、前沿论文、极端情形与边缘维度 |

## 配置要点

- **`constitution`** — 关掉会退回无约束模式，范围控制能力随之消失
- **`patchLoop`** — 适用于对**已有产出做审计/修补**的场景；普通探索型研究建议关闭
- **`votes` / `refuteRequired`** — 提高评审票数能降低误判，但成本线性上升
- **全局预算熔断** — 框架内置 agent 调用总量上限，防止高成本任务失控

## ⚠️ 成本提醒

**这套框架运行成本很高。** 单轮完整流程实测约 **250 次子 agent 调用、410 万 token、79 分钟**。

调用前必须先向用户复述这个量级并取得确认。它适合"结论错了代价很大"的任务，**不适合日常问答**。
