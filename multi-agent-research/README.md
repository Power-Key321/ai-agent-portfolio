# Multi-Agent Research Framework

**给复杂研究任务的一套多智能体编排框架：先立法，再求解，最后对抗验证。**

解决的问题很具体：当一个研究任务足够复杂、足够开放时，直接让模型去查、去总结，得到的结果**无法判断真假**——你不知道哪条结论有据可查，哪条是模型编的，哪条虽然为真但超出了问题边界。

本框架的答案是把「约束」和「验证」变成流程里的**结构性环节**，而不是靠 prompt 里写一句"请确保准确"。

---

## 核心思路

```
        传统做法                       本框架
   ┌──────────────┐          ┌──────────────────────────┐
   │  直接问模型   │          │ 0. 制宪会议 — 先立法      │
   │      ↓       │          │      ↓                    │
   │  得到答案     │          │ 1-2. 多队并行求解（受约束）│
   │      ↓       │          │      ↓                    │
   │  无法验证     │          │ 3. 对抗验证 — 专职反驳     │
   └──────────────┘          │      ↓                    │
                             │ 4-5. 评分 → 综合合成       │
                             │      ↓                    │
                             │ 6. 多轮修补 — 迭代         │
                             └──────────────────────────┘
```

### 为什么要有「制宪会议」

开放研究任务最常见的问题不是找不到资料，而是**范围无限膨胀**——越查越远，最后交付一堆正确但无关的内容。

本框架在开始前先开一场**模拟立法会议**：由一个独立的议员团（与执行研究的研究队分离，防止"为自己立法"）博弈出一份本次任务专用的**约束宪法**：

- **scope 条款** — 检索范围限定在哪
- **exclusion 条款** — 哪些方向不做
- **resource 条款** — 来源数量与深度上限
- **evidence 条款** — 什么算有效证据
- **termination 条款** — 什么情况下判定无解并停手

宪法一经颁布即**刚性锁死**（任务中途不得修改），并带**日落条款**（本次任务结束即失效，下次重新立法）。

立法程序本身借鉴了真实制度：议案相关性审查（防止夹带私货）、逐条 2/3 超多数表决、永恒条款需全票通过、一轮复议、少数意见记录。**这不是装饰**——超多数门槛能有效防止偏好聚合时出现投票循环，逐条表决能防止一揽子劫持。

## 六个设计机制

| 机制 | 作用 |
|---|---|
| **前置制宪** | 把"范围控制"从口头要求变成硬约束 |
| **先验边界** | 只承认宇宙客观边界（物理/数学/信息/计算），不承认人类主观框架 |
| **攻防一体** | 每支研究队既是参赛者、也是攻击者、还是评委 |
| **多轮修补** | 每轮必须修补上轮被攻击的漏洞，且不得通过修改约束来修补 |
| **双重边界评估** | 同时评估客观可行性与合宪性，违宪结论即使为真也淘汰 |
| **透明交付** | 宪法全文、表决记录、方案、攻击、评价全部公开可查 |

---

## 三轨裁决（质量控制的核心）

每条结论必须被明确归类到三档之一，**不允许模糊地带**：

| 裁决 | 含义 |
|---|---|
| **DEPLOYABLE** | 证据在本轮内已闭合：有引文支持 + 来源匹配 + 独立重跑通过 + 合宪 + 五视角评委无实质反驳 |
| **PROBE** | 核心断言依赖本轮内**不存在的证据**（依赖未来事件或外部实验）——诚实标注，不假装可信 |
| **REJECTED** | 有反证 / 来源不足 / 过时 / 营销内容 / 违宪 / 缺少可复现证据 |

**验证阶段的硬约束：**

- 每条结论由多个评委**专职反驳**（而非专职确认），达到反驳阈值即淘汰
- **违宪票是硬 veto**：任何评委标记违宪，整条结论淘汰，无论其是否为真
- 幸存判定需满足多数约束，防止个别评委出错时错误结论仍能幸存
- 缺少可复现证据的结论在排序中降权

## 调用方式

```javascript
const result = await Workflow({
  scriptPath: "./workflow.js",
  args: {
    task: "<复杂研究任务>",
    config: {
      constitution: true,    // 启用前置制宪会议
      patchLoop: true,       // 启用多轮修补
      maxPatchRounds: 1,     // 修补轮数上限 (1-3)
      votes: 5,              // 每条结论的对抗验证评委数
      refuteRequired: 3,     // 淘汰阈值 (≥3/5 反驳)
      maxFetch: 15,          // 抓取预算
      maxVerify: 25,         // 验证结论数上限
      teams: ["T0", "T1", "T2", "T3"]
    }
  }
})
```

### 配置要点

- **`constitution`** — 关掉会退回无约束模式，范围控制能力随之消失
- **`patchLoop`** — 适用于对**已有产出做审计/修补**的场景；普通探索型研究建议关闭
- **`votes` / `refuteRequired`** — 提高评审票数能降低误判，但成本线性上升
- **全局预算熔断** — 框架内置 agent 调用总量上限，防止高成本任务失控

## 工程细节

这套框架在六轮自审计中累计修复 40+ 项问题（完整日志见 `FRAMEWORK.md` 的版本演进章节），其中几类值得单独说明，因为它们都是**真实踩过的坑**：

- **计分 bug**：队伍定义缺少唯一标识，导致所有队伍被判为同分、冠军恒定为第一队——静默错误，不报错但结果全错
- **验证漏洞**：违宪票最初只在投票层级生效，缺少结论层级的硬否决，导致部分越界结论仍能幸存
- **上下文丢失**：多轮修补时只保留最后一轮记录，导致第三轮看不到第一轮已采纳的修补，产生冲突
- **失败韧性**：上游限流（429）导致大批 agent 失败后，加入了调用点指数退避重试与全局配额熔断

这些修复全部配有回归测试。**框架自身的正确性同样是被验证过的，不是假设的。**

---

## 诚实说明

- 这套框架**运行成本高**（单轮完整流程实测 250 次 agent 调用、约 410 万 token、79 分钟）。它适合"结论错了代价很大"的研究任务，不适合日常问答。
- 框架不保证一定找到答案。当约束下确实无解时，它会**明确输出"无解"并附上推理过程**，而不是生成一个看起来合理的结论。这类负结果同样是有价值的交付物。
- `RESULTS.md` 中的运行记录不含具体研究内容，仅保留与任务领域无关的聚合指标。
