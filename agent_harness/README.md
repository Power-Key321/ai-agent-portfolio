# Harness — 乐高式 Agent 编排框架

把 Agent 编排系统拆成**可插拔的独立模块**，而不是写死的流程脚本。不同任务类型自动装配不同的模块链，配合螺旋收敛逐轮逼近用户真实意图。

这不是一个"把 prompt 串起来"的脚本集合，而是一套带**量化门检、退化检测、失败降级与自优化闭环**的编排内核。

---

## 为什么这样设计

常见的 Agent 编排做法是一条固定流水线：所有任务都走同样的「思考→工具→回答」。问题是，写代码和做调研对流程的要求根本不同——前者需要多轮修补与回归验证，后者需要广撒网与交叉印证。

本框架的答案是**把编排结构本身参数化**：

- 编排系统 = 六大层 × 可插拔模块
- 任务类型 = 由意图路由决定
- 模块链 = 按任务类型自动装配
- 模块参数 = 由历史反馈持续调优

一句话：**不同任务走不同的流水线，而且流水线本身会进化。**

---

## 架构

```
用户输入
   ↓
意图路由（ModelRouter 三层：学习正则 → 内置正则 → 模型判定）
   ↓
┌──────────────────────────────────────────────────────────┐
│  preproc   →  decomp   →  schedule  →  context  →  execute  →  deliver  │
│  预处理       拆解         调度         上下文       执行         交付     │
│  (4 模块)    (3 模块)    (2 模块)     (2 模块)    (2 模块)    (5 模块)   │
└──────────────────────────────────────────────────────────┘
   ↓                        ↑
螺旋收敛（≤5 轮）       recovery 恢复层（5 模块，处理失败分支）
```

**合计 24 个可插拔模块**，另有独立的恢复层处理各类失败分支。

### 六大层职责

| 层 | 职责 | 关键设计 |
|---|---|---|
| **preproc** | 把模糊需求压缩成结构化意图 | 演绎式五要素压缩 + 概率分布 + 歧义检测 |
| **decomp** | 把任务拆成熵减链 | 信息源→过滤→处理→产出→验证 + 8 维补全 |
| **schedule** | 决定子任务执行顺序 | 顺序 / 并行（拓扑排序 + 并行批次） |
| **context** | 管理上下文窗口 | 分层上下文，控制多步推理的上下文膨胀 |
| **execute** | 执行 + 量化门检 | 4 道门检 + 退化 streak 计数 + 自动降级 |
| **deliver** | 交付 + 6 项自检 | 质量自评 + 代价预估 + 缺口识别 + 否定结论外部对照 |

## 六类任务策略

路由表定义在 `strategies/route_table.json`，每种策略装配不同的模块链、模型与螺旋参数：

| 策略 | 适用场景 | 默认模型 | 螺旋上限 |
|---|---|---|---|
| `code_feature` | 实现新功能 | opus | ≤5 轮 |
| `code_fix` | 修复缺陷 | sonnet | ≤3 轮 |
| `data_analysis` | 数据分析 / 统计 | opus | ≤4 轮 |
| `research` | 搜索 / 调研 | haiku | ≤3 轮 |
| `refactor` | 重构 / 整理结构 | opus | ≤4 轮 |
| `simple_query` | 简单问答 | haiku | 短路，不进螺旋 |

**三层路由**：先查学习到的正则模式（0 token 开销），未命中查内置正则，仍未命中才调用模型判定。绝大多数请求在前两层就能确定策略。

## 核心机制

### 1. 量化门检与退化检测

每个子任务的每一轮都有可判定的推进指标。连续 3 轮无推进即判定退化，自动触发该子任务的降级策略——**单点失败不污染整条链路**。

### 2. 螺旋收敛

模糊任务不要求一次到位，而是逐轮收敛：每轮补充约束、缩小半径，直到满足收敛阈值或达到轮次上限。

### 3. 反馈自优化闭环

每次交互后记录用户行为反馈（接受 / 修改 / 重来）作为**隐式评分**，反哺策略权重与路由模式学习。设计上与多因子量化模型同构：路由靠意图识别，评分靠隐式反馈。

### 4. 否定结论外部对照

框架内置一道专门机制：当某轮得出**否定性结论**（"不可能"、"已穷尽"、"无路径"）时，自动触发外部对照查询，防止把「内部模型/搜索空间的局限」误判成「问题的真实极限」。

判定结果分三态：`双重确认否定`（可信度高）/ `发现外部替代`（推翻原结论）/ `存疑否定`（标注不可靠，给出验证建议）。

## 快速开始

```bash
# 安装依赖
pip install -r requirements.txt

# 运行
python main.py "你的任务描述"
```

作为库调用：

```python
import sys
sys.path.insert(0, "<项目根目录>")

from agent_harness.adapters.claude_code import get_adapter

adapter = get_adapter()
result = adapter.start("<任务>", intent_override="<策略名>")

print(result["deliverable"])
print(result["convergence"])
print(result["gate_summary"])
```

### 模型配置

支持通过适配器接入不同模型后端。复制配置模板并填入你自己的 key：

```bash
cp deepseek_config.example.json deepseek_config.json
```

> ⚠️ `deepseek_config.json` 已在 `.gitignore` 中，不会被提交。请勿把真实 key 写进任何会被追踪的文件。

## 目录结构

```
harness/
├── core/            核心引擎（路由、收敛、反馈、元认知、成本看板…）
├── modules/         24 个可插拔模块（preproc/decomp/schedule/context/execute/deliver/recovery）
├── strategies/      任务路由表（策略 → 模块链装配定义）
├── adapters/        模型后端适配器
├── agents/          子 agent 调度（DAG 执行器、消息总线、多种 agent 类型）
├── api/             可选 HTTP 接口
├── knowledge/       知识图与记忆
├── tests/           单元测试
├── main.py          命令行入口
└── ARCHITECTURE_v1.md   详细架构文档
```
