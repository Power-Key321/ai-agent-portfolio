## 二、中文名怎么处理（关键技术事实）

**结论：`name` 字段不能写中文，但用户看到的名字可以是中文。**

从本地安装的 CodeBuddy 客户端二进制里挖出来的真实规则（不是二手资料）：

### 事实 1：`name` 必须是 ASCII 标识符

- 格式：小写字母 + 数字 + 连字符，≤64 字符，首尾不能是连字符
- **目录名必须与 `name` 完全一致**——客户端读不到 `name` 时会**回退用目录名**（`readSkillFromDirectory` 里 `extractFrontmatterField(s,"name") || Je.basename(t)`）
- 上传链接里也用这个标识符校验，写中文会在这一步挂掉

### 事实 2：客户端真正读的字段是 6 个，不是 5 个

实测 `SKILL.md` 的 frontmatter 解析代码，实际被读取的字段是：

```
name  ·  description  ·  when_to_use  ·  license  ·  allowed-tools  ·  disable
```

**`when_to_use` 就是给用户看"这技能什么时候用"的字段。** 之前那批资料说的"只认 5 个字段、没有 when_to_use"是错的。中文显示名走这里。

### 事实 3：`allowed-tools` 按**逗号**切分

客户端代码是 `c.split(",").map(d => d.trim())`。

⚠️ **空格分隔会被解析成一个叫 `"Read Write WebFetch"` 的工具。** 我之前按"可移植标准"选了空格分隔，是错的——**已全部改成逗号**。

（Claude Code 三种格式都吃，所以逗号对四端都安全。）

### 实际做法

| 位置 | 内容 |
|---|---|
| `name` | ASCII 标识符（`smart-loop` / `tech-reserve-finder`）——**不动** |
| `when_to_use` | 中文，说清"什么时候用 + 什么时候不用" |
| `description` | 中文，`长任务循环推进器 — …`，开头就是中文名 |
| `metadata.display_name` | 中文名（给上传表单抄） |
| 正文 H1 | 中文名 |

**中文名对照**：

| slug | 中文显示名 | 字数 |
|---|---|---|
| `smart-loop` | 长任务循环推进器 | 8 |
| `tech-reserve-finder` | 跨产业技术平替发现器 | 10 |
| `multi-agent-research` | 多智能体对抗验证研究框架 | 13 |
| `agent_harness` | 乐高式 Agent 编排框架 | — |

> ⚠️ **上传表单里如果有单独的「显示名称」字段，填中文名。** 这一项本机无法验证（`open.WorkBuddy.cn` 被网络策略拦截），请在提交页面确认。
> 如果表单只允许用 `name` 当显示名，`when_to_use` + `description` 就是兜底——列表页和模型路由都会读它们。

## 三、案例脱敏

### 原始 11 个案例的敏感度分级

`tech-reserve-finder` 最初有 11 个 A 级案例，公开前筛过一轮。完整分级如下：

| # | 案例 | 判定 |
|---|---|---|
| A1 | 显示面板 → 光计算推理芯片 | 🔴 **禁**（AI + 半导体） |
| A2 | 稀土分离 → 原子层沉积工艺 | 🔴 **禁**（稀土 + 半导体） |
| A3 | 聚变氚增殖包层 → 退役电池回收 | 🔴 **禁**（核聚变） |
| A4 | 高能材料药柱界面 → 固态电池界面 | 🟡 军工背景，**本次撤下** |
| A5 | 单光子探测 → 光计算精度 | 🔴 **禁**（量子 + 半导体） |
| A6 | **轨道交通牵引变流 → 大型数据中心供配电** | 🟢 **本次新增** |
| A7 | 核电压力容器锻造 → 超高真空腔体 | 🟡 核电 + 被卡方是半导体，不用 |
| A8 | 磁浮控制 → 晶圆台运动控制 | 🔴 **禁**（半导体） |
| A9 | **深海耐压结构 → 超高压化工反应器** | 🟢 保留 |
| A10 | **中药连续提取 → 化学药连续制造** | 🟢 保留（最干净） |
| A11 | **煤化工碳化 → 下一代碳材料** | 🟢 保留 |

**最终保留 4 个，全部为民用方向**：中药连续提取 / 煤化工碳化 / 深海耐压结构 / 轨道交通牵引变流。

你问的"除了 AI 推理芯片，还有哪些能不过分敏感地展现技能"——答案就是这 4 个，其中 **A6（轨道交通→数据中心供配电）是本次新补进来的**，它把"大功率电能变换"这个物理原语跨到两个完全民用的场景，最能体现方法的迁移力，且零敏感度。

### 这一轮还改了什么（降"张扬"度）

| 原来 | 现在 | 原因 |
|---|---|---|
| 「卡脖子」「受制于」「追赶台积电」 | 中性描述「推进缓慢」「供给集中度」 | 去掉对抗色彩 |
| A 级 =「全球范围内几乎没人想到」 | 「公开材料中少见直接连接」 | 不再下无法证伪的强断言 |
| 案例里点名的企业/院所 | **全部去掉**，只留产业特征 | 不点名 |
| 硬数字（10-50x、全球唯一、全球独有） | 去除，改为能力描述 | 不张扬 |
| 「军工/重工是最大的隐性技术库」 | 「极端工况行业是最大的隐性技术库」 | 去掉军工指向 |
| 内部笔记引用 `[[中国全产业链…]]` | 删除 | 别把内部笔记标题带出去 |
| 案例结尾 | 加了一句「案例只作演示，交付时必须重新做三步法」 | 明确案例是**方法演示**不是**结论清单** |

现在的正文只写到「物理同构 + 储备方 + 目标场景 + 可迁移点」四段，**不含参数、不含工艺路线、不点名任何主体**。

## 四、需要注册 / 认证吗

**需要，而且是实名认证。**

### 第 1 步：WorkBuddy 账号

手机号注册。这一步只让你**使用**平台。

### 第 2 步：开发者实名认证（发布技能的前置条件）

| 项 | 内容 |
|---|---|
| 材料 | 身份证 + 手机号 + 邮箱 + **扫脸** |
| 耗时 | 约 3 分钟 |
| 可跳过 | **不可**，未认证账号没有提交入口 |
| 收费 | 否 |

通过后需**完善开发者主页**（头像 / 20–120 字简介 / 联系方式）——这是技能详情页展示给用户的公开身份。

> ⚠️ 实名认证意味着真实身份与该账号**永久绑定**。上架内容若涉及敏感领域，责任归属是明确且可追溯的。

### 第 3 步：提交与审核

```
上传 SKILL.md + 填写技能介绍
  → 安全扫描（P0/P1/P2 分级）
  → AI 审核
  → 人工抽检
  → 上架 / 驳回（邮件通知）
```

**审核 3–7 个工作日。** 上架后后台可看安装量 / 使用量 / 评分。

## 五、上架能拿到什么

| 项 | 说明 |
|---|---|
| 曝光 | 进入 SkillHub，国内高可达渠道——**曝光量级大于 GitHub** |
| 调用 | 用户的 agent 可直接调用 |

**实际价值排序**：

1. **能力证明**——「国内主流 agent 平台有已上架技能」比 GitHub 链接更容易被国内 HR 与团队验证（这个渠道他们点得开）
2. **被动曝光**——技能详情页挂开发者主页，等于常驻公开名片
3. **收入**——两个技能都是方法论型，**不要当收入来源**

## 八、附：WorkBuddy vs 现有三端的契约差异

| 维度 | Claude Code / Codex / Cursor | WorkBuddy |
|---|---|---|
| frontmatter 字段 | 宽松，额外字段被忽略 | **客户端读 6 个**：`name` / `description` / `when_to_use` / `license` / `allowed-tools` / `disable` |
| `allowed-tools` 分隔符 | 空格 / 逗号 / YAML 列表都吃 | **只按逗号切分** |
| `allowed-tools` 权重 | 可选 | 安全审查核心项，缺失影响过审 |
| 技能名规则 | 无限制 | 小写字母 + 数字 + 连字符，≤64，**目录名须与 name 一致** |
| 技能根目录 | `~/.claude/skills/`、`~/.codex/skills/` | `~/.workbuddy/skills/` 与 `~/.codebuddy/skills/` **都会扫**；项目级 `.codebuddy/skills/` |
| 变量占位符 | `${CLAUDE_SKILL_DIR}` | `${CODEBUDDY_SKILL_DIR}`（兼容 Claude 别名） |
| 正文限制 | 无硬限制 | ≤500 行 / ≤5000 token |
| 安全分级 | 无 | **P0 / P1 / P2**，P0 硬禁止 |
| 分发 | 自建 marketplace / 官方目录 | **SkillHub**（审核 3–7 工作日） |
| 付费 | 无 | **SkillPay**（定价权 + 收款权归开发者） |

两个待上架技能均已满足：单文件、无 P0 模式、frontmatter 合规、正文远低于 500 行。

> 上表规则来自本机 CodeBuddy 客户端二进制（`resources/app/out/main.js`）实测，**不是**公开资料的转述。
> 唯一无法本机验证的是 **SkillHub 提交端的校验规则**——`open.WorkBuddy.cn` 被网络策略拦截。提交前请对照该站点确认。
