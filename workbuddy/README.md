# WorkBuddy 上架说明

> 本目录在 `workbuddy` 分支上，**不合并回 `main`**。
> `main` 保持「Claude Code / Codex / Cursor 三端通用」形态；WorkBuddy 有专属契约，单独维护。

---

## 一、上架哪几个技能

| 技能 | 上架 | 原因 |
|---|---|---|
| `smart-loop` | ✅ | 纯指令型，单文件 SKILL.md，不依赖任何运行时 |
| `tech-reserve-finder` | ✅ | 纯指令型，单文件 SKILL.md，不依赖任何运行时 |
| `multi-agent-research` | ❌ | 真正的能力在 `workflow.js`，依赖 **Claude Code 的 Workflow 引擎**。在 WorkBuddy 上只是一份读得懂但跑不动的说明书 |
| `agent_harness` | ❌ | 两个硬阻塞：① 依赖 Python 3.10+ 与 Claude Code 适配器层；② skill 名含下划线，**不符合 WorkBuddy「小写字母 + 数字 + 连字符」的命名规则**，而改名会破坏 `import agent_harness`（目录名即包名） |

**直接结论：先上 2 个。**

`agent_harness` 如果将来要上，正确做法是**拆出一个纯指令版**（去掉 Python 调用路径，只保留编排方法论），另起目录名如 `agent-orchestration`——而不是把现有目录改名。

### 为什么 `smart-loop` / `tech-reserve-finder` 是干净的

- 各只有 1 个文件（`SKILL.md`），无脚本、无二进制、无网络回调
- 全文扫描无任何 P0 敏感模式（`rm -rf /`、`dd if=`、`mkfs.`、`sudo`、`eval(`、`os.system` 等）——`agent_harness` 里那个 `sentinel.py` 的 P0 误判问题，**这两个技能完全不存在**
- frontmatter 已收敛到 WorkBuddy 的 5 字段白名单

## 二、需要注册 / 认证吗

**需要，而且是实名认证。** 分两步，缺一不可：

### 第 1 步：WorkBuddy 账号

用手机号注册即可。这一步只让你**使用**平台。

### 第 2 步：开发者实名认证（发布技能的前置条件）

| 项 | 内容 |
|---|---|
| 材料 | 身份证 + 手机号 + 邮箱 + **扫脸** |
| 耗时 | 约 3 分钟 |
| 是否可跳过 | **不可。** 未认证账号没有提交技能的入口 |
| 是否收费 | 否 |

认证通过后需**完善开发者主页**（头像 / 20–120 字简介 / 联系方式）——这是技能详情页上展示给用户的部分，等于你的公开身份。

> ⚠️ 实名认证意味着你的真实身份与该账号**永久绑定**。上架内容若涉及敏感领域，责任归属是明确的、可追溯的。这一点在下面的「披露边界」里展开。

### 第 3 步：提交与审核

```
上传 SKILL.md + 填写技能介绍
  → 安全扫描（自动，查 P0/P1/P2 分级）
  → AI 审核
  → 人工抽检
  → 上架 / 驳回（邮件通知）
```

- **审核时长：3–7 个工作日**
- 上架后可在后台查看 **安装量 / 使用量 / 评分**

## 三、上架能拿到什么

| 项 | 说明 |
|---|---|
| 曝光 | 进入 SkillHub 市场，是国内高可达渠道——**曝光量级大于 GitHub** |
| 调用 | 用户的 agent 可直接调用你的技能 |
| 收款 | SkillPay（2026-07-16 上线）：**定价权与收款权归开发者**，按调用量结算，走微信支付，**无企业规模门槛**——个人开发者可参与 |
| 门槛 | 无费用、无企业资质要求 |

**对你的实际价值排序**：

1. **能力证明**——「在国内主流 agent 平台有已上架技能」比 GitHub 链接更容易被国内 HR 与团队验证（这个渠道他们点得开）
2. **被动曝光**——技能详情页可挂开发者主页，等于一个常驻的公开名片
3. **收入**——两个技能都是方法论型，定价空间有限，**不要把它当收入来源**

## 四、⚠️ 披露边界（提交前必须自己拍板）

`tech-reserve-finder` 的 4 个 A 级案例（固态电池界面 / 深海耐压壳体 / 中药连续提取 / 煤化工碳化）此前已在公开 GitHub 仓库曝光过一次。

**但 SkillHub 的暴露面大于 GitHub**：

- GitHub 需要会翻、会搜才看得到；SkillHub 是平台内直接分发，**用户点一下就装上了**
- 实名认证后，内容与真实身份**可追溯绑定**
- 该技能正文涉及**具体产业方向**（固态电池、钠电硬碳、碳纤维前驱体等）

### 已做的防护

现有正文**只写到「物理同构 + 储备方 + 被卡方」层面**，属于"方向性观察"，不含量化参数、不含工艺路线、不含任何具体主体点名。41 大类速查表里的「（→ XXX）」映射注解在公开前已全部清空。

### 你可以做的三个选择

| 选项 | 含义 |
|---|---|
| **A. 原样上架** | 接受上述暴露面，认为内容本身是公开可讨论的方向性判断 |
| **B. 摘除 4 个 A 级案例后上架** | 只留方法论（三步法 + 41 大类 + A/B/C 分级），案例部分留在 GitHub。**推荐——方法论才是可复用的部分，案例是结论** |
| **C. 暂不上架** | 只上 `smart-loop` |

我的建议是 **B**：技能的价值在「怎么找」，不在「找到了什么」。

> 如果你要选 B，告诉我，我把 4 个案例段落从 WorkBuddy 版正文里摘掉——GitHub 版（`main` 分支）保持不动。

## 六、附：WorkBuddy vs 现有三端的契约差异

| 维度 | Claude Code / Codex / Cursor | WorkBuddy |
|---|---|---|
| frontmatter 字段 | 宽松，额外字段被忽略 | **只认 5 个**：`name` / `description` / `license` / `allowed-tools` / `metadata` |
| `allowed-tools` | 可选 | **安全审查核心项**，缺失影响过审 |
| 技能名规则 | 无限制 | **小写字母 + 数字 + 连字符**，≤64 字符，首尾不能是连字符，**目录名必须与 name 一致** |
| 安装路径 | `~/.claude/skills/`、`~/.codex/skills/` | `~/.workbuddy/skills/`；项目级 `.workbuddy/skills/`（项目级优先） |
| 变量占位符 | `${CLAUDE_SKILL_DIR}` | `${CODEBUDDY_SKILL_DIR}`（并兼容 Claude 别名） |
| 正文限制 | 无硬限制 | ≤500 行 / ≤5000 token |
| 安全分级 | 无 | **P0 / P1 / P2** 三级，P0 硬禁止 |
| 分发 | 自建 marketplace / 官方目录 | **SkillHub**（审核 3–7 工作日） |
| 付费 | 无 | **SkillPay**（定价权 + 收款权归开发者） |

两个技能均已满足：单文件、无 P0 模式、frontmatter 合规、正文远低于 500 行。
